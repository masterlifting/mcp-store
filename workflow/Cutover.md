## Operator-controlled cutover

The operator owns each gate. Do not infer approval from this checklist or from a successful local build.

1. **Identify the exact deployment.** Record the consumer, installed producer identity/version, selected archive and its verified digest, task-data roots, and the authorized maintenance window. Confirm the consumer will explicitly select the intended release; source changes alone do not update an installed MCP.
2. **Inventory every relevant copy read-only.** Include active and archived task roots, deployment backups, retained immutable archives, consumer pins, and any external working repositories in scope. Record exact paths, counts, file kinds, and hashes where authorized. Do not print or copy user task contents into public reports. Do not manually parse or edit `runtime.json`; use the applicable supported Workflow read/validate operations for task state.
3. **Find legacy-reference and immutable-snapshot evidence.** Search only an owner-designated safe document scope, never a blanket repository/archive root or all user data. If the operator cannot establish a scope that excludes credentials, tokens, keys, session files, and other secret material, stop and ask the owner; do not run the search. For that explicitly authorized scope, a read-only, path-only example is `rg -l -i --hidden --glob '*.md' --glob '*.txt' --glob '!TASK.md' --glob '!**/TASK.md' --glob '!runtime.json' --glob '!**/runtime.json' --glob '!.git/**' --glob '!**/.git/**' --glob '!build/**' --glob '!**/build/**' --glob '!bin/**' --glob '!**/bin/**' --glob '!obj/**' --glob '!**/obj/**' --glob '!**/*credential*' --glob '!**/*secret*' --glob '!**/*token*' --glob '!**/*session*' --glob '!**/*.env*' --glob '!**/*.key' 'immutable.{0,40}(snapshot|archive)|(snapshot|archive).{0,40}immutable|SPEC\.md|requirements/[0-9]+\.json|docs/requirements' <owner-designated-safe-doc-root>`. This inventories matching filenames only; do not open or otherwise inspect matching content unless the owner separately and explicitly authorizes that content inspection and its scope. Do not add roots or file types outside the authorized supporting Markdown/text document scope. A filename match is only evidence to request/perform authorized inspection, never requirement authority or permission to modify. Record matching paths and targets without exposing document contents. Preserve a target only with owner authorization, using a collision-safe destination and source-hash verification. If authorization, target identity, or collision handling is unclear, stop and ask the owner. A reference or successful copy proves neither completeness nor permission to modify.
4. **Compare each task root to the producer allowlist.** Check immediate entries and their file kinds, including reparse points and symlinks, under the target platform. Do not assume this producer scans nested `docs/`, `scripts/`, or `temp/` contents. If an entry is unsupported, unreadable, ambiguous, or cannot be inventoried, stop before installation or task creation and obtain an explicit operator disposition. Never resolve a mismatch by deleting, moving, rewriting, or silently excluding user data.
5. **Protect rollback and immutable artifacts.** Preserve the verified previous producer and its exact pin/archive for authorized rollback. Do not regenerate, replace, or hand-edit a published immutable archive, pin, task record, fingerprint, or decision. Do not introduce a migration layer or run cleanup/archive as part of producer adoption. If authorized review establishes unique normative information that must be retained, transfer only that information to the corresponding existing Workflow field through supported operations; preserve source evidence and obtain owner authorization first. Do not infer, duplicate, or discard data to force a fit. Keep schema-v1 records on the explicitly selected prior producer if they must remain operable; schema-v2 adoption does not convert them.
