## `Handoff.fs` — two-channel production-validation core

The new core replaces the prior `Receipt` + `Handoff.create` +
`Handoff.readFromDirectory` + `Handoff.bootstrapFetchCandidate` surface
with three distinct typed surfaces and one read function. No
compatibility alias is retained; the prior surfaces are retired and the
Runner's publish entrypoint fails closed until the modern workflow
adapter wires the new core.

### Type-safe digest wrappers

```fsharp
type OuterDigest         // private ctor; wraps a 64-hex lowercase SHA-256
type InnerArchiveSha256  // private ctor; wraps a 64-hex lowercase SHA-256
type VerifiedEntryName   // private ctor; wraps one validated entry name
```

`OuterDigest` and `InnerArchiveSha256` are *distinct* types at compile
time even though both wrap a 64-hex lowercase SHA-256 string. The
publisher can never accidentally substitute an outer-transport digest
for an inner-archive digest (or vice versa) at the call site; the
build fails if it tries. The only construction paths are through the
private parsers, which validate the shape.

### Channel A — `TrustedPublisherReceipt` (independently built)

Provenance evidence generated by the independently built trusted
builder job. The receipt is the **only** source of every observed
identifier (exact repo / event SHA / run-attempt / observed toolchain /
roster + per-component Config.fsx hashes / runtime paths + sizes +
hashes) the publisher uses to verify the candidate before any policy
decision runs. The receipt bytes, digest, and source path are supplied
*separately* from the runtime installation; the publisher never trusts
a candidate-supplied receipt.

Schema (schemaVersion 1, all fields mandatory; `parseTrustedPublisherReceipt`
rejects unknown fields, missing fields, null fields, malformed JSON,
wrong schema version, and inconsistent runtime triplets):

```json
{
  "schemaVersion": 1,
  "repository": "owner/name",
  "eventRevision": "<40-hex lowercase SHA>",
  "runId": "<id>",
  "attempt": "<n>",
  "trigger": "<push|...>",
  "role": "<publisher|runtime|candidate>",
  "rosterPath": "<relative path>",
  "rosterSha256": "<64-hex lowercase SHA-256>",
  "componentConfigPaths": { "<componentId>": "<relative path>", ... },
  "componentConfigShas":   { "<componentId>": "<64-hex lowercase SHA-256>", ... },
  "runtimeFilePaths":   [ "<relative path>", ... ],
  "runtimeFileDigests": { "<relative path>": "<64-hex lowercase SHA-256>", ... },
  "runtimeFileSizes":   { "<relative path>": <bytes>, ... },
  "builderSdk":     "<sdk>",
  "builderRuntime": "<runtime>",
  "builderPlatform": "<platform>"
}
```

No partial trusted runtime fields: all three runtime fields
(`runtimeFilePaths`, `runtimeFileDigests`, `runtimeFileSizes`) are
mandatory in JSON. Values may be the *consistent empty triplet* (a
prepare-time receipt carries no trusted runtime entries) or a *fully
populated cross-consistent triplet* (every path has matching digest +
size, no extra digests or sizes). Any partial combination
(non-empty + empty) is rejected.

The receipt's digest values (`rosterSha256`,
`componentConfigShas[…]`, `runtimeFileDigests[…]`) are typed
`OuterDigest` so the publisher cross-checks them against the
publisher-observed values without ever comparing them to an inner
archive digest by mistake.

`readTrustedPublisherReceiptFromFile(path)` is the only disk-side
entry; it reads the file, hashes it (defensively copies bytes), and
fills `SourceSha256` on the resulting record.

`renderTrustedPublisherReceipt(receipt)` and
`writeTrustedPublisherReceiptToFile(path, receipt)` are public so the
trusted builder job can emit the receipt; they are out of this batch's
compile scope (the builder job consumes them).

### Channel B — `PreparationReceipt` (untrusted candidate identity)

The candidate-side evidence. Carries **only** the candidate's
self-asserted identity (outer digest + size of the raw snapshot) and
the source path / file SHA. Carries **no runtime fields** and **no
toolchain values**; a candidate cannot manufacture the trust anchors a
publisher needs because none of them are recorded here.

Schema (schemaVersion 1, all fields mandatory; `parsePreparationReceipt`
rejects unknown fields, missing fields, null fields, malformed JSON,
wrong schema version, negative sizes, and non-64-hex digests):

```json
{
  "schemaVersion": 1,
  "candidateOuterDigest": "<64-hex lowercase SHA-256>",
  "candidateOuterSize":   <bytes>
}
```

`readPreparationReceiptFromFile(path)` is the only disk-side entry;
it reads the file, hashes it (defensively copies bytes), and fills
`SourceSha256`.

### Transport — `ArtifactEvidence`

The expected metadata (artifact ID / name / role / component /
repository / run / attempt / SHA) cross-checked against the observed
platform metadata, plus the actual outer digest and the raw transport
bytes. This surface **never becomes authorization by itself**; the
publisher cross-checks it against the trusted receipt and the canonical
policy.

```fsharp
type ExpectedMetadata =
    { ArtifactId: string
      ArtifactName: string
      Role: string
      Component: string
      Repository: string
      RunId: string
      Attempt: string
      Sha: string }

type ObservedPlatformMetadata =
    { ArtifactId: string
      ArtifactName: string
      Role: string
      Component: string
      Repository: string
      RunId: string
      Attempt: string
      Sha: string }

type ArtifactEvidence =
    { Expected: ExpectedMetadata
      Observed: ObservedPlatformMetadata
      ActualOuterDigest: OuterDigest
      TransportSourcePath: string
      TransportLength: int64
      RawTransportBytes: byte[] }
```

### `readRawTransport` — the only public byte-consuming entry

```fsharp
val readRawTransport:
    rawOuter: string ->
    boundedBytes: byte[] ->
    evidence: ArtifactEvidence ->
    trustedPolicy: ReleasePolicy.PolicyProjection ->
    Result<CandidateArchiveSnapshot, ReleaseError>
```

`readRawTransport` is the only public entry that consumes transport
bytes. It performs, in order:

1. Bounded byte validation: not null, length ≤ 256 MiB
   (`outerTransportMaxBytes`); the supplied length must match
   `evidence.TransportLength`; the supplied
   `evidence.ActualOuterDigest` must itself be a 64-hex lowercase
   SHA-256.
2. **Outer digest verification BEFORE any extract**: the
   publisher-computed SHA-256 of the bounded bytes must equal
   `evidence.ActualOuterDigest.Value`. A mismatch fails closed with a
   typed `IdentityMismatch("outerTransportSha256", …)`; no extraction
   happens.
3. **Schema / metadata verification BEFORE any extract**: every field
   in `ExpectedMetadata` (artifact ID / name / role / component /
   repository / run / attempt / SHA) must match the corresponding
   field in `ObservedPlatformMetadata`. A mismatch fails closed with a
   typed `MalformedArtifact(rawOuter, …)` carrying the field name and
   both observed values; no extraction happens.
4. Bounded standard-platform ZIP enumeration via
   `System.IO.Compression.ZipArchive` (NOT the canonical inner parser
   `ReleaseArchive.parse`):
   - entry count ≤ 4096 (`outerEntryCountMax`),
   - per-entry uncompressed size ≤ 256 MiB
     (`outerEntryUncompressedMax`),
   - per-entry compression ratio ≤ 200:1
     (`outerEntryCompressionRatioMax`),
   - total uncompressed ≤ 256 MiB (`outerTotalUncompressedMax`),
   - per-entry name length ≤ 256,
   - per-entry name path-safe (no `\\`, no `:`, no leading `/`, no
     `..` / `.` segments, no non-ASCII bytes),
   - per-entry name unique case-sensitively.
5. **Exact entry-set verification BEFORE any extract** against the
   canonical policy: the union of `trustedPolicy.PublishedFiles`,
   `manifestEntryName = "distribution.json"`, and
   `noticeEntryName = "NOTICE.txt"` must equal the set of names the
   archive declares. A mismatch fails closed with a typed
   `AllowlistMismatch(…)`; no manifest is read.
6. Optional bounded prep-diagnostics extraction: if and only if the
   archive declares exactly one `distribution.json` entry, the entry's
   bytes are read under the same per-entry cap and snapshotted as a
   `VerifiedEntry`. Otherwise the snapshot's manifest fields are
   `None` and the publisher is responsible for the rest.

No writes are produced. The function returns a typed
`CandidateArchiveSnapshot`.

### `CandidateArchiveSnapshot` + `VerifiedEntry` — safe verified result

Both classes store their byte arrays in **private fields** and never
expose them as public mutable references. The public surface is:

```fsharp
type VerifiedEntry =
    member Name: VerifiedEntryName
    member NameBytes: byte[]                    // with get () = Array.copy …
    member PayloadSha256: OuterDigest
    member PayloadSize: int64
    member PayloadBytesCopy () : byte[]         // defensive copy
    member PayloadStream () : Stream            // ownership-transfer stream

type CandidateArchiveSnapshot =
    member OuterDigest : OuterDigest
    member OuterSize : int64
    member InnerArchiveSha256 : InnerArchiveSha256
    member InnerArchiveSize : int64
    member ManifestEntryName : VerifiedEntryName option
    member ManifestSha256 : OuterDigest option
    member ManifestSize : int64 option
    member EmbeddedRevision : string option
    member Entries : VerifiedEntry list
    member SourcePath : string
    member SourceSha256 : string
    member HasManifest : bool
    member InnerArchiveBytesCopy () : byte[]    // defensive copy
    member ManifestBytesCopy () : byte[]        // defensive copy (empty if absent)
    member EmbeddedManifestBytesCopy () : byte[]// defensive copy (empty if absent)
    member InnerArchiveStream () : Stream       // ownership-transfer stream
    member ManifestStream () : Stream           // ownership-transfer stream
    member EmbeddedManifestStream () : Stream   // ownership-transfer stream
```

`OuterDigest` (the publisher-observed outer-transport SHA-256) and
`InnerArchiveSha256` (the publisher-observed inner-archive SHA-256)
are **separate typed fields**; their distinct types make accidental
substitution a compile-time error. The internal core reads bytes and
copies defensively at the snapshot boundary so external mutation
cannot affect the verified snapshot.

### Channel A — `TrustedPublisherReceipt` parser

Positive:
- canonical receipt (every mandatory field present, all digests
  64-hex lowercase, runtime triplet empty) parses to a
  `TrustedPublisherReceipt` whose `SourceSha256` is filled by
  `readTrustedPublisherReceiptFromFile`.

- unknown field → `MalformedArtifact` carrying the unknown field

- missing `schemaVersion` → `MalformedArtifact`.
- wrong `schemaVersion` (e.g. `2`) → `MalformedArtifact` carrying
  "unsupported trusted publisher receipt schema version".
- `eventRevision` not 40-hex lowercase → `MalformedArtifact`.
- `rosterSha256` not 64-hex lowercase → `MalformedArtifact`.
- `componentConfigShas` map missing a path that `componentConfigPaths`
  declares → `MalformedArtifact`.
- `componentConfigPaths` map missing a sha that `componentConfigShas`
  declares → `MalformedArtifact`.
- `runtimeFilePaths` non-empty but `runtimeFileDigests` empty →
  `MalformedArtifact`.
- `runtimeFileDigests` non-empty but `runtimeFilePaths` empty →
  `MalformedArtifact`.
- `runtimeFileSizes` non-empty but `runtimeFilePaths` empty →
  `MalformedArtifact`.
- a runtime digest that does not correspond to a runtime path →
  `MalformedArtifact`.
- a runtime path that has a digest but no size → `MalformedArtifact`.
- `repository` empty / null → `MalformedArtifact`.

- missing `candidateOuterSize` → `MalformedArtifact`.

### Transport — `readRawTransport` (`CandidateArchiveSnapshot`)

Each test materializes a real bounded `.zip` archive under a temp path
(no source from the candidate directory) so the
`ReleaseArchive.parse` and `ZipArchive` paths are exercised end-to-end.

Positive:
- a well-formed archive whose entry set is exactly
  `trustedPolicy.PublishedFiles ∪ {"distribution.json", "NOTICE.txt"}`
  and whose `distribution.json` payload matches the canonical manifest
  schema parses to a snapshot whose `HasManifest = true`,
  `OuterDigest`, `InnerArchiveSha256`, `ManifestSha256`,
  `ManifestSize`, `EmbeddedRevision` are populated, and every
  `VerifiedEntry.Name` is in the canonical set.

Negative:
- outer digest mismatch
  (`evidence.ActualOuterDigest.Value` differs from the SHA-256 of
  `boundedBytes`) → `IdentityMismatch("outerTransportSha256", …)`;
  no extraction happens.
- expected vs observed metadata mismatch
  (`evidence.Expected.ArtifactId <> evidence.Observed.ArtifactId`)
  → `MalformedArtifact(rawOuter, …)`; no extraction happens.
- entry set mismatch (archive has an extra file not in the canonical
  set) → `AllowlistMismatch(…)`; no extraction happens.
- entry set mismatch (archive is missing a canonical file) →
  `AllowlistMismatch(…)`; no extraction happens.
- entry name contains `..` → `MalformedArtifact` carrying "unsafe
  path"; no extraction happens.
- entry name starts with `/` → `MalformedArtifact`; no extraction
  happens.
- entry name contains `\` → `MalformedArtifact`; no extraction
  happens.
- entry name contains `:` → `MalformedArtifact`; no extraction
  happens.
- duplicate entry name (case-sensitive) → `MalformedArtifact`;
  no extraction happens.
- two `distribution.json` entries → `MalformedArtifact` carrying
  "more than one 'distribution.json' entry".
- bounded bytes exceed `outerTransportMaxBytes` → `MalformedArtifact`.
- bounded bytes that are not a valid ZIP at all → `MalformedArtifact`
  carrying "the bounded transport bytes are not a valid
  standard-platform ZIP".
- bounded bytes `Length = 0` → `MalformedArtifact` (covered by the
  same standard-platform ZIP failure).
- `evidence.TransportLength <> boundedBytes.Length` → `IdentityMismatch`.

### Safe verified result — `CandidateArchiveSnapshot` accessors

- `InnerArchiveBytesCopy ()` returns a defensive copy: mutating the
  returned array does not affect subsequent reads.
- `InnerArchiveStream ()` returns a fresh `MemoryStream` over the
  verified bytes; the snapshot's internal storage is unchanged after
  the stream is disposed.
- `ManifestBytesCopy ()` and `EmbeddedManifestBytesCopy ()` return
  empty arrays when the manifest was absent (`HasManifest = false`).

### Type-distinctness

- an `OuterDigest` is NOT assignable to an `InnerArchiveSha256` (or
  vice versa) without explicit unwrapping; the compiler rejects the
  substitution.

## Frozen three-job JSON cutover — core implementation evidence

The later approved forward-only cutover supersedes the earlier two-channel design
above:

- `infrastructure/release/Runner.fs` now exposes exactly `prepare <Config.json> <outdir>` and `publish <Config.json> <candidate-directory> --workspace-root=<trusted-checkout> --event-sha=<exactHEAD> --repo=<masterlifting/mcp-store>`. Publish rejects unknown, duplicate, missing, and empty flags; validates canonical roster/config bytes, fixed repository identity, exact event HEAD, clean checkout, and candidate data before requiring the upload opt-in/token.
- The private transport factory seam takes verified snapshot/policy/context and retains one `VerifiedCandidate.createFromSnapshot`, `ReleaseEvaluate.evaluate`, and `ReleaseTransaction.run` path. Metadata staging uses a sibling `publication` directory.
- `infrastructure/release/Handoff.fs` now contains a privately-constructed `CandidateArchiveSnapshot` and `readCandidate(candidateDirectory, expectedPolicy, eventSha)`. It requires exactly the producer archive and standalone `distribution.json`, bounds archive/member reads, rejects unsafe names and link attributes, validates the inner archive and compares standalone/embedded manifest identities and event revision. Receipt, platform metadata, and outer transport types/readers are removed.
- `infrastructure/release/Orchestration.fs` no longer writes preparation JSON or SHA diagnostics. Preparation emits only archive plus standalone manifest and refuses a non-empty output directory.
- `infrastructure/release/Release.fsproj` no longer compiles `PublisherClosure.fs`; `PublisherClosure.fs`, `Publisher.json`, and `Sources.json` are deleted. The README describes only the frozen CLI/data boundary.
